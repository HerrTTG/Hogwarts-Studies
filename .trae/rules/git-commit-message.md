提交信息（commit message）规则：

1. 语言：一律使用中文，部分重要单词可以使用中英混杂。
2. 格式：使用 `<类型>: <简短描述>` 结构。常见类型：功能、修复、重构、文档、测试、构建、样式。
3. 长度：首行（主题行）不超过 50 个字符，只写"做了什么"，结尾不加句号。
4. 详细描述：如需要补充背景、原因、影响，可在主题行后空一行，用 1-3 行简述"为什么改"和"改了什么"，每行不超过 72 个字符。
5. 语气：使用祈使句或动宾结构（如"修复登录失败时的日志泄露"），避免"我修复了""已修改"等第一人称或完成时表述。
6. 范围：涉及具体模块时可在类型后加括号注明，如 `修复(登录页): 错误提示入日志前脱敏员工账号`。
7. 提交粒度：一次提交只包含一个逻辑变更，不把无关修改混在一起。

示例：

```
修复(BasePage): 异常日志不再记录明文密码

原实现将函数fn(tools)参数全貌写入日志，存在敏感信息泄露风险。
改为只记录方法名与参数个数，并同步更新安全测试用例。
```

```
文档: 新增发布前验证清单与用户使用说明
```
